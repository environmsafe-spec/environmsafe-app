# Decisions

Each decision taken without asking, with the reason. Newest last.

| # | Decision | Why |
|---|---|---|
| 1 | Web address **records.environmsafe.com** instead of app.environmsafe.com | app.environmsafe.com already serves the Operations app (EOS). Overwriting it would break a live system. Change the `CUSTOM_DOMAIN` line in `.github/workflows/release.yml` to move it. |
| 2 | Architecture as in the brief: React + TypeScript + Vite + Tailwind, PWA, Capacitor 7 for Android, Dexie (IndexedDB) offline store, Supabase (Postgres, Auth, RLS, Storage, one Edge Function), Cloudflare Pages, GitHub Actions | All free, one code base for web and phone. Capacitor 7 / Vite 7 / TypeScript 5 chosen over the very newest majors because they are mature and well documented. |
| 3 | **Sync design**: every change is saved on the device first and queued; the database function `sync_apply` merges per field (last edit wins by the time the edit was made), records every overwritten edit in `sync_conflicts`, and never drops a refused change (it stays on the Sync screen with the reason) | Meets "last edit wins per field, visible conflict list, never silently lose data". Runs with the user's own rights, so Row Level Security applies to every synced change. |
| 4 | Admin actions **require two-step sign-in in that session**: an Admin without it is treated as Office by the database | "TOTP required for Admin" enforced in the database, not only in the screens. |
| 5 | No public sign-up: a database trigger refuses any new account whose e-mail an Admin has not approved; Admin creates users and sets passwords in the app (Edge Function `admin-users`) | Works even if the dashboard "allow sign-ups" switch is left on; nothing depends on e-mail sending. |
| 6 | Pressures stored in pascals, shown in bar / kg/cm² / psi / MPa / kPa | Brief: store SI, show the user's unit. 1 bar = 1.0197 kg/cm², 1 kg/cm² = 14.223 psi (unit tested). |
| 7 | PSV tolerance: ASME VIII UG-126 (±2 psi to 70 psi, ±3 % above) and ASME I bands, chosen per test | The two rules used for process valves and boiler valves. Shown as a check, the inspector decides. |
| 8 | Next due date: asset's own interval, else the equipment type default; for "half remaining life" types the shorter of half the lowest remaining life and the cap | API 510 / 570 practice. Every default is marked "confirm against code edition, client requirement and local regulation" and is editable. |
| 9 | Documents are built once as a neutral layout and rendered to **Word (docx library) and PDF (pdfmake)** in the browser | No paid server; both outputs always match. PDF text uses a renamed Latin subset of Liberation Sans ("ES Report Sans", metric-identical to Arial, SIL OFL licence); Word names Arial. |
| 10 | PDF page margins equal the Word margins (T1100 R900 B800 L900 twips); the PDF top margin grows to fit the header, as Word does | Word pushes the body down when the header is taller than the margin; the PDF does the same so both look alike. |
| 11 | Word contents page lists the sections without page numbers; the PDF contents page has page numbers | A Word page-number contents field needs the reader to press "update fields" when opening, which looks unprofessional. |
| 12 | Numbers are allocated by the database when a document is issued (reports when generated); numbers are never reused, including numbers typed by hand | "Never reuse a number". Offline drafts show "number on sync". |
| 13 | Photos resized on the device to 1600 px on the long side and re-encoded to about 250 KB | Free storage is 1 GB; uploads over poor networks. |
| 14 | Backups: nightly database export + user list + file manifest, restored every night into a fresh empty PostgreSQL 17 and compared row by row, kept 30 days as an encrypted private GitHub artifact. Files themselves are in "Export everything" (manual ZIP) | A fresh *Supabase* project is not possible on the free plan while you have two active projects; a fresh PostgreSQL with the same migrations proves the same thing. File copies nightly would exhaust the free 500 MB artifact space. |
| 15 | Keep-alive every 2 days from GitHub Actions | Free projects pause after about 7 days idle. |
| 16 | APK built in GitHub Actions | This build container cannot reach Google's Android repositories (dl.google.com). |
| 17 | Signing keystore generated here (RSA 4096, valid to 2056), committed only **encrypted** (AES-256, PBKDF2 200 000 rounds); the passphrase is a GitHub secret | One secret to manage; the key never exists in plain form in the repository. |
| 18 | Local end-to-end tests run against a small Supabase stand-in (`scripts/mock-supabase.mjs`) backed by the real migrations and RLS; CI also runs them against a real local Supabase stack | Docker images could not be downloaded in this container (registry rate limit). The stand-in is never deployed. |
| 19 | Interface in English with a dictionary (`src/lib/i18n.ts`) and start/end (not left/right) layout | Arabic can be added later by adding a dictionary. |
| 20 | Free-tier limits checked 2026-10-11 by web search (re-check yearly). Supabase free: 500 MB database, 5 GB egress, 2 active projects, pause after 7 days without activity; file storage is quoted as 500 MB by some sources and 1 GB by others, so the storage meter assumes **500 MB** (change it in Settings → Company → Options once confirmed on supabase.com/pricing). Cloudflare Pages free (official limits page): 500 builds/month, 20 000 files per site, 25 MiB per file, 100 custom domains per project. GitHub Actions private repo: 2 000 minutes/month, 500 MB artifact storage | The meter warns at 70 %. Escape paths are in docs/RUNBOOK.md. Sources: developers.cloudflare.com/pages/platform/limits; supabase.com/pricing (via third-party summaries). |
